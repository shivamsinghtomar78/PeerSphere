# 29 — Frontend Quality Checklist

## Before merge

- [ ] Next.js/TypeScript lint, type check, and relevant tests pass.
- [ ] Route authorization and error boundaries are present.
- [ ] Reusable component is used before adding a new pattern.
- [ ] Loading, empty, error, disabled, success, and permission-denied states are verified.
- [ ] Keyboard, focus, screen-reader labels, contrast, zoom/reflow, reduced motion, and reduced transparency are checked.
- [ ] Mobile, tablet, laptop, and desktop layouts are reviewed.
- [ ] No match score or recommendation promises selection.
- [ ] Glass is selective, performant, and has opaque fallback.
- [ ] Text overflow, dense tables, filters, charts, and dialogs received visual QA.

## Acceptance

A screen is not complete because it looks polished. It is complete only after functional, responsive, accessibility, performance, and visual evidence is recorded.
